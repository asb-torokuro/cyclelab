# CycleLab バックアップ・復旧方針

本番Supabaseプロジェクトでは、Supabaseの組み込みバックアップとPoint-in-Time Recoveryの利用可否を契約プランで確認し、保持期間、復旧目標（RPO/RTO）、復旧担当者を運用台帳に記録します。認証ユーザー、プロフィール、将来の活動データを同一の復旧対象として扱います。

マイグレーションは`supabase/migrations`に不変の順序付きSQLとして保存し、Gitのmainにレビュー済みコミットを保存します。バックアップ復旧後は、マイグレーション履歴、RLS有効化、policy、grant、外部キー、インデックスを検証してからアプリを再接続します。

復旧テストは専用の非本番Supabaseプロジェクトで、バックアップ取得、別環境への復元、マイグレーション再適用、2ユーザーのRLS分離、ログインとプロフィール読み書きを確認します。本番データに対する破壊的な復旧試験は行いません。Secret Key、Service Role Key、データベースパスワードはバックアップ文書やGitに保存しません。
